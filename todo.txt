C. CFOUR reader (parse_cfour_output, parseCFOUR_forWilson.py)
-------------------------------------------------------------
[ ] C1  diphess is not symmetric. CFOUR's dipole files list both orders of a mode pair, from numerical
        derivatives: CCSDTcc_pVQZ/dipolez lines 8 and 10, (9,10) -0.0025711085 and (10,9) -0.0025712225.
        getDipoleDers_anharm (parseCFOUR_forWilson.py:520-533) copies each line into its own slot. wilson's check
        then fails: diphess[1,5,2] = 2.52302e-05 vs diphess[5,1,2] = 2.52368e-05. The Gaussian reader writes one
        value to both slots (parseGaussian_forWilson.py:630-631).
        Fix: average the two orders; if the file has only one order, copy it to both. Unblocks wilson G8.
[ ] C2  Always-true conditions. `if 'a' or 'b' in requested_data` is always True, so every call reads every file
        (parse_wilson_obtainer.py:278, 293, 302, 316, 346, 358). HFcc_pVQZ has no MOLDEN, so any request there
        raises FileNotFoundError.
        Fix: any(k in requested_data for k in (...)), as in parse_gaussian16_output. Read MOLDEN only for
        equilibrium_geometry, atoms and normal_modes. Take the mode count for parse_coriolis (line 319, now from
        MOLDEN) from the harmonic frequencies. Every property that uses fundamentals_harmonic_int (lines 329-362)
        must still read the out file first (like A2).
[ ] C3  qff in au is 320-800x too large (median 568), against Gaussian formaldehyde (T4). getQuarticPost
        (parseCFOUR_forWilson.py:432-466) only divides by the mass factor; getCubicPost (369-430) also multiplies
        by sqrt(w_i w_j w_k) and divides by the unit factor. qff_rc is right. No EVV term uses qff; wilson S3 uses
        qff_rc.
        Fix: convert as getCubicPost does (4 frequencies, the quartic factor), or stop returning CFOUR qff.
        Prefer the fix: both readers then return the same keys (Rules). Check with T4.
[ ] C4  linear: wilson never passes linear (DataOriginInfo has no such field), so CFOUR always takes mode 7 as the

N. Normal modes (wilson G9)
---------------------------
Gaussian numbers modes two ways: the harmonic section (H order) and the anharmonic section (A order). Inside one
Gaussian origin every property is in A order, except normal_modes.
wilson's load does not ask for normal_modes, and the evaluator does not read them (system_data.py:235-236). One
wilson test does: test_integration.py:141 asks wilson_data_obtainer for them (Gaussian formaldehyde,
B3LYP/cc-pVQZ) and pins normal_modes[0], a flat vector of 12 values, in H order. N1 and N3 change it [wilson].
[ ] N1  [decide] Mode order of normal_modes. Now, without reindex_modes, normal_modes is in H order and the rest in
        A order. Formaldehyde: normal_modes[0] is the out-of-plane mode (1203 cm-1); nc_sqrt_eigval[0] is the C-H
        stretch (2879 cm-1). wilson cannot ask for reindex_modes (no field in DataOriginInfo).
        Ways: normal_modes in A order like the rest; everything in H order; a DataOriginInfo field [wilson].
[ ] N2  Failures: ACAC and ACDM raise "cannot reshape ... into shape (0,3,3)"; CO returns 0 modes
        (get_normal_modes, parseGaussian_forWilson.py:992).
[ ] N3  One shape for both readers. Now a dict {mode: vector}: Gaussian keys 0 .. n-1 and flat vectors (3 x atoms);
        CFOUR keys from 7 (7-12 for formaldehyde) and vectors of shape (atoms, 3). wilson's MolSystemData.eigenvecs
        is typed as a numpy array, but stores the dict as it comes (from_datadict, system_data.py:308).
        Choose one, e.g. an array (modes, atoms, 3) with modes 0 .. n-1, in one unit.
