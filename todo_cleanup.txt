Goal
----
Clean code, and a core that gives the right numbers or a clear error.
"Core" = what wilson uses: parse_from_source, the two readers behind it, PKG_ROOT, setup_logger (todo.txt, Rules).

Done when:
    1. `import CQCParse` works after a plain `pip install .` (Q1, Q2).
    2. CQCParse holds only code that the core or the tests use. Tools kept for the example files are marked as such
       (Q3, Q4, Q5).
    3. Bad input gives a clear error, never a wrong or empty result: an unknown name, a wrong source_type, an empty
       section in a file (Q6, Q7, Q8, A6).
    4. The unit conversion of each property is written out once, and checked against the other program (T4, R4).
    5. wilson's tests pass with this branch (L1, T6).

Not part of this goal (they stay in todo.txt): R2, N1-N3 (except N1's first step), X1, A3, A4, L2. These are new
physics choices or wilson features, not fixes.


How to work
-----------
The rules of todo.txt apply. In short:
    - After each change: CQCParse's tests (248 pass, about 3 s) and the baseline (T2).
    - A cleanup must not move a number. If the baseline moves during a cleanup, stop and find out why.
    - A change that moves a number on purpose (only T4/R4 here): give the reason in the commit message, and run
      wilson's tests too (T6).
    - Before each delete: search the name in CQCParse, tests and wilson_gv/src. The dead-code check (Q4) follows
      names, so a name used only as a string (getattr, a file name) would be missed.
